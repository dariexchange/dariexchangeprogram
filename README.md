# DARI 웹사이트 — 실제 운영 배포 안내

이 폴더의 사이트는 **설정 파일(config.js)이 있으면 실제 서버(Supabase)에 연결**되고,
없으면 지금까지 보신 **체험 모드**로 실행됩니다.

서버에 연결하면 한국 운영진·HAN.AL 운영진·참가자가 **어느 기기에서 접속하든 같은 데이터를 보고**,
한 사람이 바꾼 내용(보강 일정, 인증 사진, 출석, Zoom 정보, 학습자료)이 다른 사람 화면에 **자동으로 반영**됩니다.

## 폴더 구성

| 파일 | 설명 |
|---|---|
| `index.html` | 웹사이트 전체 (화면 + 기능) |
| `config.example.js` | 서버 연결 설정 견본 → `config.js`로 복사해서 사용 |
| `supabase/schema.sql` | 데이터베이스 구조, 접근 규칙, 보강 규칙, 파일 저장소 |
| `supabase/setup.sql` | 운영 기수·정규 시간·운영진 계정 초기 설정 |

## 배포 순서 (약 30분)

### 1. Supabase 프로젝트 만들기
1. https://supabase.com 에 가입하고 **New project**를 만듭니다. (무료 요금제로 시작 가능, 지역은 `Northeast Asia (Seoul)` 권장)
2. 데이터베이스 비밀번호는 따로 안전하게 보관하세요.

### 2. 데이터베이스 만들기
1. 대시보드 왼쪽 **SQL Editor** → **New query**
2. `supabase/schema.sql` 내용을 전부 붙여 넣고 **Run**
3. `supabase/setup.sql`의 기수 번호와 운영진 이메일을 실제 값으로 바꾼 뒤 **Run**
   - 운영진 계정이 아직 없다면 **Authentication → Users → Add user**로 먼저 만드세요.

> 이전 버전의 `schema.sql`을 이미 실행한 프로젝트라면 표 구조가 달라 그대로 덮어쓸 수 없습니다. 아직 실제 데이터가 없다면 새 Supabase 프로젝트를 만들어 이 버전으로 시작하는 것이 가장 간단합니다.

### 3. 연결 설정 파일 만들기
1. 대시보드 **Project Settings → API**에서 `Project URL`과 `anon public` 키를 복사합니다.
2. `config.example.js`를 복사해 `config.js`로 이름을 바꾸고 두 값을 붙여 넣습니다.
   - `service_role` 키는 절대 넣지 마세요.

### 4. 사이트 올리기 (택 1)
- **Netlify Drop**: https://app.netlify.com/drop 에 이 폴더(index.html, config.js 포함)를 끌어다 놓기
- **Vercel**: 새 프로젝트 → 이 폴더 업로드 (빌드 설정 없음, 정적 사이트)
- **GitHub Pages**: 저장소에 올리고 Pages 활성화

### 5. 로그인 주소 등록
대시보드 **Authentication → URL Configuration**에서
- **Site URL**: 배포된 사이트 주소 (예: `https://dari.netlify.app`)
- **Redirect URLs**: 같은 주소를 추가

### 6. 운영 시작
1. 운영진이 사이트에서 이메일 로그인 → **운영 관리**
2. **일정 · Zoom**: 1회차 활동일과 시작 시간을 골라 4회차 일정 만들기 → 회차별 날짜·시간·유형·주제 수정 → Zoom 링크 한 번 등록(모든 참가자에게 같은 링크 표시)
3. **참가자 · 매칭**: 참가자 이름·이메일·구분·카카오톡 ID 등록 → 매칭 (후보는 언어 수준이 비슷한 순 → 공통 관심사 많은 순)
4. 참가자는 등록된 이메일로 로그인 링크를 받아 접속하면 자동으로 본인 계정에 연결됩니다.

## 서버가 강제하는 규칙
브라우저를 조작해도 우회할 수 없도록 데이터베이스에서 검사합니다.

- 보강 신청은 1인 1회: 본인이 신청한 보강만 셈 (파트너가 신청한 보강은 제외 · 인증 사진을 올린 뒤에는 다시 신청할 수 없음)
- 신청은 해당 회차 수업 시작 3시간 전까지
- 보강 일시는 지금 이후 ~ 다음 회차 수업 시작 전
- 보강 일정 수정·취소는 인증 사진을 올리기 전, 다음 회차 수업 시작 전까지 (팀원 누구나)
- 인증 사진은 보강 시작 시각부터 보강일 23:59까지
- 운영진이 출석 처리하면 두 참가자 모두 출석으로 변경
- 참가자는 본인·본인 팀 데이터만 조회 (파트너의 이메일·카카오톡 ID 비공개, 다른 팀 사진·수료증 접근 불가)
- 출석 상태는 출석 · 결석 · 보강 예정 세 가지
- 학습자료는 한국 운영진·HAN.AL 모두 한국어·아랍어 자료를 등록·삭제 가능
- 수료증 파일은 운영진만 올릴 수 있고, 참가자는 본인 것만 내려받기 가능

## 배포 후 꼭 확인할 것
- [ ] 두 운영진이 **서로 다른 기기**에서 로그인해 보강 목록과 인증 사진이 똑같이 보이는지
- [ ] 운영진이 Zoom 정보를 바꾸면 참가자 화면에 바로 반영되는지, 입장 버튼으로 실제 Zoom 회의가 열리는지
- [ ] 학습자료를 올리면 참가자 자료실에 바로 나타나고, 휴대폰·PC 브라우저에서 다운로드되는지
- [ ] 수료증을 올리면 해당 참가자 출석 화면에서 내려받아지는지
- [ ] 참가자 휴대폰에서 인증 사진 업로드가 되는지

## 알아 둘 점
- **로그인 메일 발송 한도**: Supabase 기본 메일 서버는 시간당 발송 수가 적습니다. 참가자가 한꺼번에 로그인하는 날에는
  **Authentication → Emails → SMTP Settings**에 Gmail 등 별도 메일 서버를 연결하세요.
- **지원서·면접·선발 결과** 기능은 아직 포함되지 않았습니다.
- 개인정보(이메일 등)는 운영 목적으로만 사용하고, 기수 종료 후 보관 기간에 맞춰 삭제하세요.
